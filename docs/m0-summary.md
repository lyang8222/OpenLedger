## 关键发现

1. **Vision 中文 OCR 可用**：本机离线识别真实支付截图稳定，无需云端服务。
2. **平台识别靠结构词而非品牌词**：微信页面常出现"财付通 / 交易单号 / 商户单号 / 经营单号"；支付宝页面常出现"付款方式 / 商品说明 / 商家订单号 / 订单金额 / 清算机构 / 账单管理"。品牌词（微信支付 / 支付宝）在部分页面未被 OCR 读到，不能作为唯一依据。
3. **标签与值分列排版**：微信/支付宝详情页的"标签列"和"值列"在 OCR 中按行返回，标签的下一个值可能出现在几行之后。提取规则需要"按标签定位 + 跨行找首个匹配值"，而不是简单取下一行。
4. **金额方向**：消费为负数（-35.00），花呗还款为正数（780.96），信用卡还款为正数（311.19），需要保留正负号语义。
5. **单号打码**：部分支付宝页面显示"0321\*\*\*\*\*\* 点击查看订单号"，需标记为"已打码"而非解析失败；用户可后续在确认页手动补录。
6. **转账场景**：微信"扫二维码付款-给心想事成"这类转账页的商户名在"给"之后，需要独立模板。
7. **云闪付**：页面以"银联交易详情"为标题，金额带 ¥/￥ 与正负号（+ 为收入）；状态由"交易类别"决定（消费/入账）；交易标识取"参考号"（页面中最后一个纯数字长串）。
8. **抖音**：页面含"抖音支付/抖音月付/月付账单信息"；交易单号在"交易单号"标签后；"删除"按钮、状态栏时间等 UI 元素需要从商户候选中排除。

## 已验证的版式类型

- 微信支付详情（交易详情 + 当前状态/收单机构/支付时间/支付方式/交易单号/经营单号）
- 微信扫码转账详情（转账时间/转账单号/收款方服务）
- 支付宝消费账单详情（订单金额/付款方式/商品说明/收单机构/清算机构/收款方全称/订单号/商家订单号）
- 支付宝花呗还款（还款成功/创建时间/订单号）
- 云闪付交易详情（银联交易详情/卡号/交易时间/订单金额/交易类别/商户编号/凭证号/参考号）
- 抖音账单详情（抖音支付/月付账单信息/支付时间/交易单号/商户单号/商品订单）

## 对 M1 的建议

1. 把解析规则从硬编码改为 JSON 模板驱动（平台 → 版式 → 字段锚点），便于后续覆盖平台改版。
2. 金额保留正负号；打码单号与缺失字段进入"待确认"状态，由确认页人工补录。
3. 用同一套测试向量建立回归测试，防止模板调整破坏已有识别率。
4. 已覆盖四平台；后续建议补充各平台不同系统版本、更多商户类型与退款/售后页的样本。
